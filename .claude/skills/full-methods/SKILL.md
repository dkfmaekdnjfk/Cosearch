# Full Methods

연구 내용을 누락 없이 이해하고 실제 계산까지 추적할 수 있는 HTML 연구 보고서를 작성한다. 연구논문의 Methods 형식과 문체를 따른다. 아래 원문은 이 스킬의 최상위 작성 지침이며, 후속 실행 기준이 원문을 대체하거나 축약하지 않는다. 프로젝트별 대상·용어·경로·디자인은 해당 프로젝트의 지침과 사용자 요청에서 확인한다.

## 최상위 지침 원문

1. 연구내용을 빠짐없이, 그리고 명료하게 이해할수 있도록 하는 'full methods' 와 같은 문서를 html 형태로 작성시킴(+ research paper의 methods와 같은 형식과 문체로 작성할 것)

2. 신조어와 약어 남발하지 않도록 하고, 필요에 따라 사용한다면 반드시 누락없이 그에 대한 설명이 포함되도록 self-contained 자료로 만들 것.(우리에게 너무 자명한 수준의 용어나 약어는 물론 불필요)

3.  가능하면 복잡한 상황을 명확하게 전달하기 위해 수식을 이용하고, 수식의 정의, 노테이션을 명확히 빠짐없이 포함하도록 할것.

4. 이상의 내용을 작성할 때, 실제 결과를 뽑는데 이용한 python code를 라인 바이 라인으로 읽으면서 내용이 정확하고, 빠짐없이 서술되었는지 확인하도록 시킬 것.

## 적용 범위

원문의 Python 코드 대조 원칙은 다른 언어·노트북·워크플로에도 동일하게 적용한다. 실제 분석 언어와 실행 경로를 확인하며 Python 사용을 전제로 자료를 변경하지 않는다.

- 새 보고서는 연구질문과 분석 범위를 먼저 확인한다. 기존 보고서 보완은 최신 HTML·원본 연구노트·결과 파일·현재 사용한 그림을 확인하고 요청 범위만 수정한다.
- 새 버전을 요청하면 먼저 원본을 복사하고 보존한다. 연구 제목에는 작업 이력·수정 사유·검증 상태를 덧붙이지 않는다. 버전은 파일명과 재현 기록으로 관리한다.
- 문서 작성 요청을 새 분석·재분석·그림 생성의 승인으로 확대하지 않는다. 검산, 실제 원 분석 재실행, 기존 캐시 재사용과 문서 생성을 구분한다.
- 한국어를 작성할 때는 사용 가능한 `korean-copy` 기준을 함께 적용한다. 결과 해석은 `research-interpretation-review`의 관련 기준을 사용할 수 있다. 해당 스킬이 없어도 아래 절차를 수행한다.

## 근거를 먼저 확인한다

1. 실제 결과를 생성한 분석 진입점에서 호출 함수를 따라 입력·전처리·분석 대상 선정·통계량·귀무분포·검정·보정·그림 생성까지 해당 코드를 줄 단위로 읽는다. 해당 분석에서 수행하지 않은 단계는 추가하지 않는다. README나 계획서는 탐색 안내로 사용할 수 있으나 실제 구현 대조를 대신하지 않는다.
2. 함수의 기본값과 실제 호출에 전달한 인자를 구분한다. 배열의 축·단위·관측 단위·분모·연산 순서·제외 기준·동률 처리·난수/전수 배정·수치 허용오차를 확인한다. 적용되지 않은 대안 함수나 과거 설정을 현재 방법으로 서술하지 않는다.
3. 입력 → 계산 함수 → 산출물 → 본문 절·그림·표를 연결한다. 저장 캐시·CSV·원문과 설명이 다르면 근거를 추적하여 실제 구현을 설명한다. 불일치를 숨기기 위한 코드 변경이나 임시 계산으로 맞추지 않는다.
4. [근거·재현 연결 기준](references/evidence-and-reproduction.md)을 읽고 코드 대응, 재현 명령과 참고문헌의 근거 위치를 작성한다.

## 문서 구성과 설명

기본 흐름은 **개요·주요 결과 → Methods → 연구질문/가설별 Results → 통합 해석 → 분석 코드와 재현 근거 → 보조 자료 → 참고문헌과 원문**이다. 연구 특성과 사용자 지시에 맞게 조정하며 불필요한 절을 채우지 않는다.

긴 HTML 보고서는 본문을 읽는 중에도 사용할 수 있는 목차를 제공한다. 단순한 상단 링크 나열로 대신하지 않는다. 참고 디자인의 탐색 방식과 본문의 제목 위계를 함께 적용하며, [목차·탐색 설계 기준](references/report-navigation.md)을 따른다.

- Methods는 자료 구성·전처리·계산 순서·통계 가정·검정 질문을 논문 문체로 설명한다. 계산을 따라가는 데 필요한 정의는 HTML 본문 안에서 완결한다. 프로젝트 약어·새 기호는 처음 등장할 때 실제 대상과 의미를 정의한다.
- 수식은 LaTeX로 작성하고 모든 인덱스·행렬 축·변수·정규화·분모·범위와 단위를 설명한다. 본문 안의 변수·확률식·비교식도 동일한 수식 표기를 사용한다. 파일명·API 이름을 수학 변수로 변환하지 않는다. 오프라인 HTML에는 기존 렌더링 방식에 맞는 MathML 또는 로컬 수식 렌더러를 사용한다.
- 가설별로 관찰 → 검정 근거 → 구체적인 해석과 의미가 이어지게 배치한다. 관찰과 검정과 결론을 여러 Results로 분산하지 않는다. 상세 수치는 보조 자료에 두고 본문에서 정확히 인용한다.
- Figure 앞 본문에는 목적·비교 이유·그림의 구성을, 뒤 본문에는 실제 점·연결선·분포·축에서 판단할 근거와 결론을 작성한다. 캡션에는 측정·표현 방식을 기재한다. 그래프에 없는 계산·검정의 결론은 해당 계산·검정을 보여주는 그림에서 설명한다.
- 해석은 ‘다르다·바뀐다·유의하다’의 반복으로 끝내지 않는다. 무엇이 어떻게 달라졌고 연구 대상에 어떤 의미가 있는지 측정량의 정의와 관찰 근거로 구체화한다. 측정하지 않은 현상이나 검증하지 않은 인과관계를 확인한 사실로 추가하지 않는다. 관찰 결과, 연구 대상에 관한 해석, 해석이 성립하는 조건을 연결한다.
- 유의한 결과에는 검정 이름·조건·표본 단위와 p-value를 명시한다. 여러 검정을 탐색한 경우 선택 근거 없이 하나를 대표 p로 제시하지 않고 검정 질문별 결과를 함께 제시한다.
- 작은 표본 때문에 가능한 최소 p가 제한된 경우 실제 산출 p와 이론적 최솟값을 함께 제시한다. 최솟값에 도달한 관찰과 실제 방향의 혼재를 구분한다. 계산한 p를 ‘구할 수 없었다’로 바꾸거나 제약을 다른 검정에 확대하지 않는다.
- 강조 방식은 참고 보고서와 사용자 지시를 따른다. 배경색·굵기·밑줄을 사용한다면 연구질문에 답하는 중요한 결과와 구체적인 해석을 선별하여 적용한다. 제한점이나 통계적 주의사항의 과도한 반복·강조가 주요 결과를 가리지 않도록 한다.
- 보조 비교·긴 방법론·검토 원문은 필요에 따라 별도 문서로 연결한다. 별도 파일에는 본 보고서로 돌아가는 경로를 둔다. 원 연구노트는 보존한다. 검토가 덜 된 참고자료는 확인된 결과와 구분한다.
- 참고 디자인이 있으면 그 구성과 시각적 위계를 따른다. 사용자 요청과 문서 목적에 맞게 표현 방식을 결정한다. Figure·Table 번호, 본문 인용, 목차의 순서·위계와 문서 간 링크를 함께 정리한다.

## 완료 확인과 전달

- 변경 후 저장 파일을 다시 읽고, 본문과 코드·수치·현재 그림의 대응을 확인한다. 기존 수치·그림·해석 보존 요청에는 실제 보존 여부를 대조한다.
- 재현 명령의 진입점·옵션·작업 폴더·환경·읽기/쓰기 대상을 확인한다. 실제 수행한 검증과 과거 검증을 구분하고 전체 재실행을 하지 않았으면 수행한 범위를 명시한다.
- 검증 방법은 변경 범위와 사용자 제약에 맞게 선택한다. 문구 수정에 브라우저 검수를 자동으로 추가하지 않는다. 사용자가 브라우저 실행을 금지하면 headless 실행도 포함하여 금지 범위를 따른다. 파일·DOM 검증을 화면 검수로 보고하지 않는다. 작업을 위해 실행한 보조 프로세스는 종료 시 정리한다.
- HTML과 필요한 근거 자료의 경로를 전달한다. 사용자가 요청한 경우에만 공유용 ZIP을 생성하며 [ZIP 전달 기준](references/evidence-and-reproduction.md#zip-전달)을 적용한다.
