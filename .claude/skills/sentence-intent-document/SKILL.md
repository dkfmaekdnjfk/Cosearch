# 문장별 작성 의도 검토 문서

문장을 많이 작성한 뒤 설명을 덧붙이는 대신, 각 문장이 필요한 이유를 검토하며 본문을 누적한다.
왼쪽에는 실제 문서, 오른쪽에는 선택한 표현의 뜻과 작성 의도를 표시한다.
특정 분야의 가설·자료·용어·경로는 정해 두지 않는다.

## 문장을 누적하는 방식

- 사용자와 정한 목적에서 출발한다. 이전 문서의 분류·가설 수·목차를 새 설계의 전제로 삼지 않는다. 기존 자료와 방법은 재사용할 수 있지만, 예전에 사용했다는 사실로 필요성을 정당화하지 않는다.
- 사용자가 정한 검토 단위만 제안한다. 한 문장씩 검토하는 중에는 다음 문장이나 전체 개요를 미리 작성하지 않는다.
- 제안에는 문장과 선택 이유를 함께 제시한다. 앞의 어떤 주장이나 미해결 질문에서 이어지는지, 무엇을 밝히거나 구별하는 데 필요한지 설명한다.
- 문서 작성을 요청받았다면 승인된 내용은 실제 파일에 반영한다. 문서 위치를 물었을 때 채팅만 작성한 상태를 저장 완료로 설명하지 않는다. 사용자가 제안·검토만 요청하면 파일에는 반영하지 않는다.
- 기존 문서는 최신 내용을 읽고 필요한 부분만 수정한다. 새 문서나 사본은 요청한 범위에서 생성한다. 합의되지 않은 문장으로 빈 부분을 채우지 않는다.

## 문장과 표현의 검토 기준

1. **대상과 주장:** 누가 또는 무엇이 어떤 조건에서 무엇을 한다는 문장인가? 대상·수량·단위·범위가 필요한 곳에 있는가?
2. **논리적 역할:** 정의, 질문, 근거, 대안 설명, 비교 설계, 판단 중 어떤 역할인가? 왜 바로 앞 내용 다음에 필요한가? 이미 말한 내용을 다른 말로 반복하지 않는가?
3. **표현의 선택:** 명사와 동사가 실제 무엇을 가리키는가? 한 줄로 뜻이 전달되지 않으면 표현을 나누어 설명한다. 낯선 표현을 다른 미정의 표현으로 바꾸지 않는다.
4. **방향과 비교:** 증가·감소나 전후·대소가 중요한 문장은 방향과 비교 대상을 명시한다. 방향에 제한이 없다면 제한이 없음을 밝히고, 실제 비교에서 방향을 무시한다는 뜻과 구분한다. '변한다', '영향', '기준', '같은 비중'만으로 구체적인 관계나 연산을 대신하지 않는다.
5. **근거와 선택:** 사실·관찰·가정·제안을 구분한다. 예시 수치는 예시임을 표시한다. 실제 자료를 인용하면 확인한 근거 위치를 남긴다. 비교 기준이나 허용 범위가 미정이면 확정된 것으로 쓰지 않는다.

검토 항목을 매번 모두 나열하지 않는다. 선택한 표현을 이해하는 데 필요한 설명만 작성한다.
뜻, 선택 이유, 앞 문장과의 연결을 구별하되 같은 설명을 여러 항목에 복제하지 않는다.
방법을 제안한다면 절차뿐 아니라 그 방법으로 구별할 내용과 비교 조건이 필요한 이유를 설명한다.
논리적 연결을 나중에 보완했다면 최초부터 정한 의도로 소급하지 않는다.

## 현재 디자인과 동작을 재사용한다

[assets/sentence-review.html](assets/sentence-review.html)을 복사해 승인된 내용으로 수정한다.
새 디자인을 추측해 다시 만들지 않는다. 템플릿의 일반 예문은 동작 설명용이며, 실제 문서에는 승인된 문장만 유지한다.
사용자가 디자인을 변경하면 해당 요청을 우선한다.

- **한 행 헤더:** 작은 제목과 날짜 또는 문서 정보만 같은 행에 둔다. 과도한 제목 크기·세로 여백·사용법 문구를 추가하지 않는다.
- **왼쪽 본문:** 일반 문서 크기의 글자로 문장을 누적한다. '첫 문장', '두 번째 문장' 같은 순서 제목을 붙이지 않는다. 내부 이동용 ID는 안정적으로 유지한다.
- **표현 선택:** 뜻이 이어지는 표현을 클릭 대상으로 만든다. 모든 조사·낱말을 기계적으로 분할하지 않는다. 선택한 표현만 본문에서 강조한다.
- **오른쪽 설명:** '작성 의도' 아래에 선택한 표현의 설명만 표시한다. 왼쪽의 표현을 선택 제목·소제목·설명 머리말에서 반복하지 않는다. 숨겨진 제목은 인쇄 때 설명을 구분하는 용도로 사용할 수 있다.
- **역방향 참조:** 설명에서 앞 내용을 가리키면 '첫 문장' 같은 번호가 아니라 내용명으로 링크한다. 클릭하면 해당 문장으로 이동하고 잠깐 강조한다. 읽던 설명과 선택 상태는 유지한다.
- **읽기 우선:** 설명을 무조건 한 줄로 줄이거나 길게 늘리지 않는다. 핵심 의미를 전달하는 문장에만 하이라이트를 적용하고, 보충 설명은 일반 본문으로 둔다.
- **좁은 화면:** 본문 다음에 설명을 배치하고 선택한 설명으로 이동할 수 있게 한다. 설명을 읽고 본문으로 돌아갈 수 있어야 한다.
- **키보드·인쇄:** 선택 표현을 Tab·Enter로 조작할 수 있게 한다. 인쇄에서는 숨겨진 설명을 모두 표시한다. 외부 폰트·서버·인터넷 없이 열리는 단일 HTML을 기본으로 한다.

본문 문장과 오른쪽 설명을 중복된 두 본문으로 만들지 않는다.
기존 설명을 삭제하지 않고 해당 표현에 연결하되, 불필요한 반복이나 잘못된 내용의 수정은 사용자 요청 범위를 따른다.

## 수정 후 확인

- 승인된 문장만 본문에 있는지, 문장 내용과 수치가 보존됐는지 다시 읽는다.
- 표현의 `aria-controls`·`href`와 설명 ID가 대응하는지, 역참조 대상 문장 ID가 존재하는지 확인한다.
- 표현 선택 시 해당 설명 하나만 표시되는지, 역참조가 설명을 바꾸지 않고 이동·강조하는지 확인한다.
- 검증은 변경 범위에 맞춘다. 문구 수정에 화면 검토를 자동 추가하지 않는다. 사용자가 화면 검토를 맡았거나 브라우저 사용을 금지했으면 브라우저·headless 검토를 실행하지 않는다. 코드 검증을 실제 화면 확인으로 보고하지 않는다.
- 실제 파일 경로와 수행한 수정만 간결하게 전달한다. 문서 작성은 새 조사·분석·외부 공유의 승인이 아니다.
