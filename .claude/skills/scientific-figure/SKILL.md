# Scientific Figure

연구질문 → 비교 기준 → 시각적 표현 → 독자가 확인할 관찰 → 해석이 이어지도록 제작한다. 과학적 비교와 최종 크기의 가독성을 모두 충족해야 한다.

## 필수 Gate와 진행 조건

그림 제작·검수·수정에 착수하면 반드시 [Gate 0–4 체크리스트](references/validation.md#필수-gate-체크리스트)를 읽고 해당 작업에 적용한다. Gate 0은 설계와 제작 전에, Gate 1은 자료와 그림을 대조할 때, Gate 2–4는 최종 출력 검수 때 수행한다. 새 figure와 큰 구성 변경은 해당 Gate 전체를 수행한다. 국소 수정은 변경 부분과 그 영향이 미치는 패널·출력에 관련된 항목을 모두 수행하고 적용되지 않는 항목은 이유를 기록한다.

각 항목은 실제 파일·자료·렌더를 확인한 근거와 함께 통과, 수정 필요, 확인 불가 또는 해당 없음으로 판정한다. 추정이나 성공 로그만으로 통과시키지 않는다. Critical은 즉시 중단해 원인을 해결하고, Major는 수정 후 영향을 받은 Gate를 다시 통과해야 한다. 필수 항목을 확인할 수 없으면 완성본으로 전달하지 않는다. 설계·자료 정의의 문제가 발견되면 근거를 확인하고 1단계로 돌아가 설계를 수정한 뒤 영향을 받는 단계를 다시 수행한다. 독립 독자 시험의 실시 여부는 실제 수행과 구분한다.

## 범위와 프로젝트 설정

- 요청이 설계만이면 설계안을, 문구·색·범례 수정이면 해당 부분을, 제작이면 실제 figure를 완성한다. 작은 수정에 전체 절차를 반복하거나 원자료 재분석을 추가하지 않는다.
- 프로젝트 지침과 기존 figure 코드를 먼저 확인한다. 루트 또는 `obsidian/00_Meta/`의 `FIGURE_GUIDELINES.md`가 있으면 해당 프로젝트에만 적용한다. 없으면 사용자 요청과 현재 자료에서 조건을 확인한다.
- 제작 설정 전에 기존 디자인 시스템을 찾는다. Cosearch의 `code/scripts/FIGURE_STYLE.md`와 `code/scripts/_figstyle.py`가 있으면 두 파일을 읽고 [Nature 디자인 시스템 연계](references/nature-design-system.md)를 따른다. Nature 스타일은 별도 스킬이 아니라 재사용할 디자인 시스템이다.
- 명시된 데이터·코드·필터·통계 결과를 재사용한다. 그림 개선을 위해 표본 제외, 새 검정, 지표 변경을 조용히 추가하지 않는다. 신규 분석은 사용자가 요청한 범위에서만 수행한다.
- 기존 결과·그림은 보존하고 새 산출물의 위치를 구분한다. 단순 수정 요청에서 불필요한 보고서·테스트·브라우저를 만들거나 실행하지 않는다.

## 1. 그림이 답할 질문

새 figure나 큰 구성 변경에는 짧은 설계 기록을 작성한다. 기존 작업 노트나 코드의 설명을 이용해도 된다.

- 질문과 실제 결과가 뒷받침하는 주장 한 문장씩.
- 독자가 먼저 봐야 할 시각적 관계 한 문장. 예: ‘조건마다 두 방법의 성능 간격과 그 예외가 보인다.’ ‘성능을 비교한다’ 같은 작업명으로 대신하지 않는다.
- 비교 조건, 한 점·선·행의 관측 단위, 독립 표본과 반복 측정의 관계.
- 각 패널의 x축·y축에 놓을 변수와 단위, 변수의 종류·범위·표시 순서 및 선택 이유. 연속 변수가 측정·계산한 값인지 비교를 위해 연구자가 조절한 설정값인지 구별하고, 이산적으로 지정한 값인지 연속 범위의 값인지 확인한다. 어떤 변수가 연구질문을 가장 잘 비교하게 하는지 대안과 함께 판단한다.
- 대응 키, 지표·단위·변환·정렬·자료 포함 기준, 불확실성과 기준선의 정의.
- 용도, 최종 폭·높이, 필요한 파일 형식, 목표 저널이 있다면 제출 단계.

현재 자료에서 알 수 있는 것은 직접 확인한다. 결과 해석을 바꾸는 미확정 정의만 질문한다. 저널 미정은 작업 중단 사유가 아니다. 최종 크기와 제작 가정을 명시하고 범용 설정으로 진행한다. 자료가 없으면 배치 도식까지 작성하며 실측값·p-value를 만들지 않는다. **새 figure나 큰 구성 변경에서 질문·축·변수의 의미·관측 단위·비교 기준 등 설계에 필요한 사항이 미확정이면 확인할 때까지 다음 단계로 넘어가지 않는다.** 제작·검수 중 미확정 사항이 발견되면 근거를 확인하고 1단계의 설계에 반영한 뒤 영향을 받는 단계를 다시 수행한다. 확인할 수 없으면 미완료 상태와 필요한 정보를 알린다.

## 2. 표현과 패널 구성

[표현 선택 기준](references/design.md)을 새 설계 또는 표현 변경 때 읽는다.

- 독자가 실제로 비교할 위치·길이·방향·분포·기준선과의 관계를 특정한다. “직관적이다”로 선택 이유를 대신하지 않는다.
- 실질적인 대안이 있을 때 비교하고 선택 이유를 간단히 기록한다. 사소한 수정에 대안 여러 개를 강제하지 않는다.
- 예시·개별 자료·집단 요약·대조의 역할을 분담한다. 같은 계산을 여러 그림에 표시한 것을 독립적인 증거로 설명하지 않는다.
- 전체 figure와 필요한 개별 패널이 모두 읽히도록 배치한다. 논문의 통합 figure와 발표 슬라이드는 서로 다른 최종 크기에 맞춰 구성한다.
- 문헌 사례를 참고할 때는 그림 자체와 caption·관련 Methods를 확인한다. 저자가 명시하지 않은 제작 의도는 분석자의 추론으로 표시한다.
- 새 설계나 큰 구성 변경에서는 사용자가 제공했거나 프로젝트에 등록된 figure 설계 참고 보고서의 실제 논문 그림과 분석을 먼저 살펴보고, 해당 자료가 없다면 적합한 논문 원그림·caption·관련 Methods를 찾아 비교 목적이 유사한 참고 원그림을 선택한다. 그림·caption·관련 Methods를 대조해 참고할 배치·범례·축 설정과 자료 차이로 적용하지 않을 사항을 기록한다. **참고 원그림과 필요한 설명을 확보·확인하지 못하면 제작으로 넘어가지 않는다.**
- 새 설계나 큰 구성 변경에서는 표현하려는 비교·정보와 각 패널의 축·배치·표기 방식에 대해 [참고 figure의 근거 정리](references/design.md#참고-figure의-근거-정리)를 수행한다. 비교 과제와 자료 구조가 맞는 실제 원그림을 우선하고, 가능한 경우 영향력 지수가 높은 저널의 피인용 수가 높은 논문도 찾아 대조한다. 각 선택의 출처·패널·적용 이유와 자료 차이를 기록한 뒤 제작한다.

## 3. 제작

[제작 기준과 Matplotlib 예시](references/production.md)를 읽고 필요한 설정만 적용한다. 기존 디자인 시스템의 설정을 우선하며, 문서의 범용 시작값은 디자인 시스템이 없을 때만 사용한다. 출력 목적이나 사용자 지시로 변경한 설정은 이유와 함께 기록한다.

- 기존 plotting 함수·언어를 우선 사용한다. 수치 그래프는 데이터와 연결된 plotting 도구로 제작한다.
- 최종 물리 크기에서 글자·선·기호·여백을 설정한다. 논문 도판을 큰 canvas에서 제작한 후 무심코 축소하지 않는다.
- Figure 전체에 적용할 역할별 글씨 크기와 선 굵기를 먼저 정한다. 같은 역할의 축 라벨·눈금·범례·패널 문자·제목은 각 역할별로 모든 패널에서 통일하고, 같은 역할의 축선·데이터선도 통일한다. 사용자나 프로젝트가 지정한 참고 도판과 같은 표시 크기로 비교하고 최종 pt·가독성을 확인한다. 패널 폭별 비율로 글씨를 따로 정하지 않는다.
- 데이터 영역을 먼저 배치한다. 큰 제목·부제·설명 도식을 기본으로 추가하지 않는다. 필요한 정의는 가까운 범례나 캡션으로 전달한다. 각 패널의 축 안쪽에서 관측값이 한쪽에 몰리고 큰 빈 영역이 생기는지 확인하고, 축 범위·패널 비율과 기준선의 역할을 검토해 비교가 잘 보이도록 조정한다. 조건 수나 색의 수만으로 정보 과밀을 판단하지 않는다.
- 데이터 식별·재현·오해 방지를 위해 디자인 시스템에서 요구하는 하단 캡션·파라미터는 장식용 설명 블록과 구분하여 유지한다. 간결한 배치를 이유로 필수 정의를 그림 밖 문서에만 옮기지 않는다.
- 색과 기호의 의미를 figure 사이에서 유지한다. 비교 대상과 밀도에 따라 직접 라벨·공유 범례·개별 범례를 선택한다.
- 중요 자료가 투명도나 요약선 아래 사라지지 않게 한다. 중첩을 해소해도 측정값과 실제 대응은 보존한다.
- 원본 데이터, plotting 코드, 적용 설정, 최종 파일을 연결한다. 데이터 선별·집계가 발생했다면 행 수와 대응 키를 확인한다.

## 4. 검수와 수정

[필수 Gate 체크리스트](references/validation.md#필수-gate-체크리스트)를 항목별로 실행하고, [검수 절차](references/validation.md)에 따라 발견 사항을 수정·재검수한다.

1. 자료와 기호·집계·오차 표시·검정 대상이 일치하는지 확인한다.
2. 최종 파일을 렌더링해 전체와 밀집 패널을 직접 본다. 축·단위·범례·통계·기호의 겹침과 잘림을 수정한다. 수치·글자 구조 검사로 시각 검수를 대체하지 않는다.
3. 논문용 PDF는 `scripts/preflight_pdf.py`를 적용할 수 있으면 목표값을 지정해 실제 크기·글자·선·폰트를 검사한다. 지원하지 않는 항목은 다른 방법으로 확인한다.
4. 새 설계나 큰 구성 변경은 참고 원그림과 최종 출력을 비슷한 패널 표시 크기로 나란히 비교한다. 긴 설명 없이 핵심 비교가 읽히는지, 글자·기호·데이터 영역·범례·축이 그 비교를 돕는지 [전달 검수](references/validation.md#핵심-비교의-전달과-참고-figure-대조)로 판정한다. 참고 원그림과 대조하지 못하면 전달 단계로 넘어가지 않는다.
5. 새 figure나 큰 구성 변경은 [독립 에이전트의 무정보 검토](references/validation.md#독립-에이전트의-무정보-검토)를 실행한다. 완성 도판만 제공하고 축·패널·정보·표기에서 어색하거나 일반적이지 않은 점을 지적받는다. 각 지적을 실제 figure 레퍼런스와 대조하고 판단·수정·재검수한다. 별도 에이전트를 사용할 수 없다면 미수행으로 기록하고 완료하지 않는다.
6. 수정한 패널과 전체 배치를 다시 확인한다. 브라우저가 필요 없는 PNG·PDF 도판에는 브라우저를 실행하지 않는다.

자료 불일치·잘못된 pairing은 먼저 해결한다. 판독 불가나 잘림이 남으면 수정하고, 도구 제약 때문에 확인하지 못한 부분은 완료로 기록하지 않는다. 장식의 작은 차이로 불필요한 승인 절차를 만들지 않는다.

수치·출력 검수와 전달 검수는 별개다. 겹침이 없고 디자인 시스템을 호출했어도 핵심 비교를 긴 설명으로 대신해야 한다면 배치를 수정한다. 차이가 작거나 없는 결과도 읽혀야 하며, 전달력을 높인다는 이유로 차이를 과장하지 않는다.

## 5. 전달

요청한 최종 figure와 재생성 가능한 코드·설정, 필요한 caption을 제공한다. 사용한 입력과 수행한 검수 및 확인 결과를 기록한다. 설계·해석에 필요한 사항이 미확정이면 확인 후 1단계로 돌아가 반영하고 영향을 받는 제작·검수를 다시 마친다. 확인할 수 없다면 완성본으로 전달하지 않는다. 기존 실행 기록이 있으면 재사용한다.

Caption은 관측 단위·변환·오차·검정을 정의한다. 본문 해설은 어떤 시각적 관계가 질문에 답하며 무엇을 뜻하는지 설명한다. 값의 증가·감소나 유의성만 반복하지 않는다.

근거와 배포 상태: [출처와 적용 범위](references/provenance.md). 프로젝트별 지표·세포형·검정·팔레트는 범용 기본값으로 포함하지 않는다.
