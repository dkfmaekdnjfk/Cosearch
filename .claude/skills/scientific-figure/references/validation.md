# Figure 검수

## 필수 Gate 체크리스트

출처: figure 설계 참고 보고서의 「LLM Figure 산출물 검수 Gate」를 범용 절차로 정리했다. 각 체크는 실제 적용 대상과 근거를 확인하고 판정한다. 해당 없는 항목은 이유를 기록한다. 새 figure·큰 구성 변경에는 전체를 적용하고, 국소 수정에는 변경과 영향 범위의 모든 항목을 적용한다. 실제 독자 시험의 수행 여부는 자기 검토와 구분한다.

### 판정과 진행

- **Critical — 즉시 중단:** 자료 조작·누락, 관측 단위 오류, 잘못된 pairing, 축·범례와 조건의 불일치, 원자료와 불일치, 근거 없는 결과·p값. 원인을 해결하고 관련 자료·설계와 Gate를 다시 확인한다.
- **Major — 수정 후 재검수:** 핵심 요소의 겹침·잘림, 최종 크기에서 판독 불가, 축 범위나 패널 비율 때문에 데이터 영역 내부에 불필요하게 큰 빈 공간이 남아 비교가 작게 보이는 경우, 같은 figure의 같은 역할 글씨나 선 굵기가 패널별로 달라진 경우, 글씨 크기나 선 굵기가 부적절해 읽기·비교·시각적 위계를 해치는 경우, 목표 저널 규격 위반, 색만으로 구분되는 핵심 비교, 깨진 글꼴, 빠진 패널, 불충분한 해상도. 수정하고 영향을 받은 Gate를 다시 확인한다.
- **Minor — 마감 수정:** 의미를 바꾸지 않는 간격·대소문자·소수점·범례 순서 불일치. 누적되어 비교를 방해하면 Major로 다룬다.
- Critical·Major가 남거나 적용되는 필수 검사를 확인할 수 없으면 완성본으로 전달하지 않는다. 실제 확인한 것과 확인하지 못한 것을 구별한다.

### Gate 0 — 제작 입력과 설계 고정

- [ ] Figure의 질문, 자료가 뒷받침하는 주장, 독자가 먼저 볼 시각적 관계를 각각 한 문장으로 정한다.
- [ ] 논문·발표 등 용도, 최종 폭·높이, 파일 형식, 목표 저널과 제출 단계를 정한다. 저널 미정이면 용도에 맞는 시작값을 정한다.
- [ ] 패널별 x·y 변수·단위·범위·표시 순서와 선택 이유를 확인한다. 각 변수가 실측·계산값인지 조절한 설정값인지, 연속 범위인지 이산적으로 지정한 값인지 구별한다.
- [ ] 한 점·선·행의 관측 단위, 독립 표본 수, 반복 측정 관계, 대응 키를 실제 입력에서 확인한다.
- [ ] 지표, 변환·정규화·정렬·선택·시간 구간·결측과 포함·제외 기준을 확인한다.
- [ ] 조건·집단 등 변수와 색·모양·선·패널의 대응, 사용할 색상 사전과 기준선을 정한다.
- [ ] 입력 자료·코드·스타일 설정·출력의 경로와 버전 또는 hash를 연결한다. 생성 전에는 출력 경로를 정하고 생성 후 버전 또는 hash를 기록한다.
- [ ] 새 설계나 큰 구성 변경은 제공된 참고 보고서 또는 적합한 논문에서 비교 목적이 유사한 실제 figure를 찾고 원그림·caption·관련 Methods를 대조해 적용할 배치·범례·축과 차이점을 기록한다.

필수 정의가 미확정이면 확인하고 설계를 갱신한 뒤 진행한다. 자료가 없으면 layout plan까지만 만든다. 참고 원그림과 필요한 설명을 확인하지 못한 새 설계·큰 구성 변경은 제작으로 넘어가지 않는다.

### Gate 1 — 자료와 과학적 무결성

- [ ] 모든 입력 행의 포함·제외·결측 처리를 추적하고 총수를 대조한다. 모든 결과 행을 확인한다.
- [ ] 독립 표본과 ROI·세포·trial·pair·추정값의 수를 구별하고, 표시한 n이 실제 집계 단위와 일치하는지 확인한다.
- [ ] 대응선의 양 끝이 실제 같은 개체·표본의 관측값인지 pairing key로 확인한다.
- [ ] 좌표·색·조건·범례·요약 통계·검정 대상이 실제 자료와 계산 결과에 대응하는지 확인한다.
- [ ] error bar·band·음영의 계산과 caption 정의가 일치하고 산포와 추정 불확실성이 구별되는지 확인한다.
- [ ] zero·chance·identity·fold=1 등 기준선이 질문과 지표에 맞는지 확인한다.
- [ ] 비교하는 heatmap의 색상 범위와 실제 zero 위치가 같도록 확인하고, 비교 축의 scale·aspect가 일치하는지 또는 차이의 이유가 명시되는지 확인한다.
- [ ] trial 평균과 단일 trial의 일관성을 구분하고, 정규화·smoothing·정렬·투영·선택이 크기와 시간 해상도에 미치는 영향을 밝힌다.
- [ ] 주장에 필요한 조건·집단·개체가 그림에 빠지지 않았는지 확인한다.

### Gate 2 — 최종 크기의 시각 검사

- [ ] 실제 최종 mm로 출력하고 전체를 100% 크기로 직접 본다. 축·단위·눈금·n·범례·p값·수식이 읽히는지 확인한다.
- [ ] 밀집 패널을 확대해서 점·선·오차 표시와 라벨이 겹치거나 잘리지 않는지, 점 크기·투명도·테두리가 핵심 자료를 지우지 않는지 확인한다.
- [ ] 작은 표본의 대응점과 선을 셀 수 있는지 확인한다. 동일값 중첩은 데이터값을 보존하는 제한된 가로 jitter나 개수 표시로 드러낸다.
- [ ] 자료·요약·기준선의 선과 명도 위계, 같은 행·열의 plotting area·baseline·패널 문자 정렬을 확인한다.
- [ ] 범례의 색·모양·선이 실제 mark와 같고 자료를 가리지 않는지 확인한다. 공유 범례는 해당 패널 가까이에 두고 예외 mapping을 표시한다.
- [ ] 각 패널에서 축 안쪽의 값·오차막대·기준선이 차지하는 범위와 비어 있는 영역을 확인한다. 예를 들어 값이 y축 위쪽에 모여 하단 대부분이 비어 있다면, 0이나 다른 기준값의 역할과 비교 대상 간 공통 축이 필요한지 확인한 뒤 표시 범위·패널 비율 또는 전체 범위와 확대 패널을 함께 쓰는 대안을 비교한다. 불필요한 빈 영역으로 비교가 작게 보이면 Major로 판정해 수정하고 최종 출력에서 다시 확인한다. 축 이름·주석과 패널 사이의 간격은 가독성과 정보 전달을 기준으로 별도로 판단한다.
- [ ] Figure 전체의 축 라벨·눈금·범례·패널 문자·제목의 크기와 축선·데이터선·기준선 굵기를 역할별로 확인한다. 같은 역할의 글씨나 선이 패널마다 다르면 Major로 판정해 통일하고, 좁은 패널은 배치·폭·줄바꿈·범례 위치로 해결한다.
- [ ] 사용자나 프로젝트가 지정한 참고 도판과 같은 표시 크기로 대조하고 최종 pt와 데이터선·개별선·기준선의 위계를 확인한다. 글씨 크기 또는 선 굵기가 읽기·비교를 해치면 각각 Major로 판정하고 수정한 뒤 내부 빈 공간과 함께 재검수한다. 패널 폭별 비율에 맞추려고 같은 역할 글씨를 패널마다 조정하지 않는다.
- [ ] 패널 간격·주석과 통계 공간을 확인하고 라벨·주석이 다른 패널 또는 canvas 경계와 충돌하지 않도록 수정한다.
- [ ] 흑백에서 핵심 조건이 위치·모양·선종류·라벨로 구분되는지 확인한다. protan·deutan 모사를 각각 확인하고 사용 도구·모델과 결과를 기록한다.
- [ ] 96–150 dpi 축소 preview와 고해상도 최종 render를 각각 직접 확인한다. 자동 bbox 통과만으로 겹침이 없다고 판정하지 않는다.

### Gate 3 — 출판 파일 검사

- [ ] 목표 profile에 맞는 글자 pt·선 pt·폭·높이를 확인하고 PDF page box 또는 SVG physical dimensions를 측정한다.
- [ ] 그래프의 글자·축·선은 편집 가능한 vector인지, 사진·heatmap 등 raster의 실제 배치 크기 대비 effective dpi가 충분한지 확인한다.
- [ ] 폰트 포함 여부와 μ·Δ·−·수식·소수점 표시를 확인한다. PDF 텍스트를 선택·추출할 수 있는지 검사한다.
- [ ] 최종 export에서 raster·링크·clipping mask·transparency의 누락이나 변형이 없는지 확인한다.
- [ ] 편집기에서 마지막으로 저장한 최종 파일을 다시 렌더링하고 실제 이미지를 확인한다.
- [ ] 요청된 main·extended·supplementary 파일별 포맷, 파일 크기·이름·패널 순서·caption 참조·범례 번호를 대조한다.
- [ ] PDF 자동 검사를 적용할 수 있으면 목표값을 명시해 실행하고 결과를 확인한다. 자동 검사가 지원하지 않는 시각 항목은 직접 확인한다.

### Gate 4 — 읽기 시험과 전달

- [ ] 본문 없이 최종 figure를 보고 무엇을 비교하는지, 점 하나와 독립 표본이 무엇인지, 각 조건이 어디에 있는지 확인한다.
- [ ] 평균과 개별 변화의 관계·예외, error/ellipse/음영의 의미, 주장의 근거가 되는 시각적 관계와 그림만으로 판단할 수 없는 범위를 확인한다.
- [ ] 독자가 다른 결과를 읽을 여지가 있으면 표현·축·범례·패널 순서를 고치고 Gate 2–4를 다시 실행한다.
- [ ] 새 설계·큰 구성 변경은 참고 원그림과 최종 figure를 비슷한 패널 크기로 나란히 보고 자료 영역·글자·기호·범례·축과 핵심 비교를 대조한다.
- [ ] 새 figure·큰 구성 변경은 별도 에이전트에게 도판만 제공해 축·패널 구성·정보·표기를 검토받고, 각 지적을 figure 레퍼런스와 대조해 판단·수정·재검수한다. 아래 「독립 에이전트의 무정보 검토」를 따른다.
- [ ] 실제 독자에게 시험할 수 있으면 같은 질문을 묻고 결과를 기록한다. 실제 독자가 없으면 자기 검토를 수행하고 독립 독자 시험은 미실시라고 명시한다. 10초·30초는 보고서의 권장 시간이며 고정 통과 기준이 아니다.
- [ ] Figure ID·질문·입력 버전/hash·설정·실제 mm·최종 파일·확인한 렌더·색 검수·발견 문제와 수정·재검수 결과를 기존 기록에 남긴다. 각 문제는 패널·대상·문제·수정·재검수 결과를 구분한다.

### 자주 발생하는 실패와 수리

| 발견 | 수리 후 다시 검사 |
|---|---|
| 큰 슬라이드를 논문 폭으로 축소해 글자·선이 작아짐 | 최종 mm canvas에서 배치와 글자·선 크기를 다시 설정한다. |
| 비교 heatmap마다 autoscale을 사용 | 공통 색상 범위·기준값·colorbar를 설정한다. |
| 조건을 색만으로 구별하거나 범례가 멀리 있음 | 적절한 위치·기호·선 또는 직접 라벨과 가까운 범례를 적용한다. |
| 평균 막대가 개별값·대응을 가림 | 자료 구조에 맞는 대응점 또는 변화량 표현을 사용한다. |
| 동일값 중첩이나 낮은 불투명도로 관측이 사라짐 | 값 보존 가로 jitter·개수 표시 또는 mark 크기·대비를 조정한다. |
| 통계 주석·글자·범례가 자료나 다른 패널을 가림 | 통계 공간·패널 배치·간격을 조정한다. |
| PNG를 PDF로 감싸거나 tight crop으로 목표 치수가 달라짐 | vector와 raster를 적절히 출력하고 최종 page box·텍스트·해상도를 다시 확인한다. |

## 독립 에이전트의 무정보 검토

새 figure나 큰 구성 변경에서 최종 도판을 만든 뒤 실행한다. 별도 에이전트는 대화 이력을 넘기지 않는 새 컨텍스트로 시작하고, 검토 대상의 최종 렌더 이미지와 검토 요청만 제공한다. 연구 질문·설계 의도·자료·코드·caption·기존 레퍼런스·예상 답·의심 사항은 제공하지 않는다. 에이전트가 다른 프로젝트 문서나 작업 이력을 열지 않고 도판만 보고 판단하도록 요청한다.

1. **검토 요청:** “이 그림만 보고 x축·y축, 패널의 배치와 분포, 전달되는 정보와 표기 방식에서 어색하거나 일반적이지 않은 점을 지적해 주세요. 각 지적의 패널과 실제 보이는 근거, 독자가 어떻게 이해할 수 있는지 적어 주세요.” 도판 안에 적힌 축·범례·주석은 그대로 제공한다.
2. **독립 결과 수령:** 원문 지적과 그림에서 읽은 내용을 기록한다. 추측과 도판에서 확인되는 내용을 구분한다. 검토자가 적절성을 판단할 정보가 없다고 답하면 그 자체도 기록한다.
3. **레퍼런스 확인:** 제작 담당자는 지적별로 기존 근거를 다시 열고, 필요하면 같은 표현을 쓴 논문 figure를 추가로 찾는다. 원그림·caption·관련 Methods와 패널 번호를 확인하며, 가능한 경우 높은 IF 저널의 피인용 수가 높은 논문을 포함한다. 유사한 표현의 존재, 관측 단위·축·자료 구조·비교 목적이 얼마나 맞는지, 해당 선택이 여기서 적절한지는 각각 판단한다.
4. **판정과 수정:** 각 지적에 대해 근거 출처와 함께 수정 또는 유지의 이유를 기록한다. 수정이 필요하면 설계·도판을 고치고 영향을 받는 Gate를 다시 실행한다. 설계 정의에 영향을 주면 1단계로 돌아간다.
5. **최종 확인:** 변경한 최종 렌더를 다시 확인하고, 주요 수정이 독립 검토의 판독 문제를 해결했는지 확인한다. 실제 독립 검토가 수행되지 않았으면 완료로 표시하지 않는다.

별도 에이전트에 검토 지침과 이미지 외의 배경 정보를 제공하면 무정보 검토가 아니므로 다시 수행한다. 에이전트가 없거나 원그림·설명을 확인할 수 없는 지적은 미확인으로 남기고 완성본으로 전달하지 않는다.

## 자료와 해석

- 입력 경로와 출력 연결, 포함·제외·결측 건수, pairing key, 집계 단위를 확인한다.
- 그림의 좌표·색·표본 수·요약 통계·오차·검정 표시를 실제 계산 결과와 대조한다.
- 모든 결과 행의 처리 여부를 추적하되 표본을 임의로 줄여 검사하지 않는다. 필요한 경우 전체 행의 자동 검산과 대표 패널의 시각 확인을 병행한다.
- 투영·정렬·정규화·확대가 해석에 영향을 주면 caption에 정의한다.

## 자동 PDF 검사

`preflight_pdf.py`는 `pymupdf` 모듈을 제공하는 PyMuPDF가 필요하다. PyMuPDF 2.0에서 실행 점검했다. 설치된 작업 환경을 우선 사용한다. 의존성을 찾지 못하면 환경의 패키지 사용 정책을 따르며, 스크립트 자체가 설치·네트워크 요청을 수행하지는 않는다.

스킬 폴더를 기준으로 실행 예:

```sh
python3 scripts/preflight_pdf.py /absolute/path/figure.pdf \
  --width-mm 180 --height-mm 100 --min-font 7 --min-stroke 0.5 \
  --require-text --require-embedded-fonts
```

표준 출력으로 JSON을 반환한다. 지정한 기준 위반은 exit 1, 실행 오류는 exit 2, 위반이 검출되지 않으면 exit 0이다. 상한은 필요한 경우에만 `--max-font`, `--max-stroke`로 지정한다. 기본값은 저널 규정을 강제하지 않는다. 다중 페이지 문서에 크기 기준을 지정하면 모든 페이지에 적용된다.

최종 PDF 렌더 이미지가 필요하면 `--render-dir /new/output/directory --dpi 150`을 추가한다. 해당 폴더가 이미 있으면 덮어쓰지 않고 종료한다. 입력 PDF는 수정하지 않는다. 출력 PNG를 이미지 열람 도구로 직접 확인한다.

검사 범위: 페이지 치수, 추출 가능한 글자의 크기·페이지 경계, PDF가 보고한 선 굵기, 폰트 포함 여부, raster의 배치 크기와 추정 DPI. 윤곽선으로 변환된 글자, 투명도, 클리핑·변환된 선의 실제 시각적 두께, 의미적 겹침은 완전히 검출하지 못한다. 이미지 DPI도 제안 정보이며 mask·회전·의도적인 저해상도 자료는 직접 해석한다.

## 실제 이미지 확인

- 최종 사용 크기에 가까운 전체 보기와 밀집 영역의 확대 보기를 모두 확인한다. 화면 확대만으로 인쇄 가독성을 단정하지 않는다.
- 축·소수점·단위·수식·범례·p-value의 판독, 패널 간 간격·정렬, 라벨·점·요약선의 겹침을 확인한다.
- 기준선과 자료선, 평균과 개별 자료, 산포와 추정 불확실성을 혼동할 여지가 있는지 본다.
- 색 제거·축소·기호 중첩으로 주된 비교가 사라지는지 확인한다.
- 수정 후 마지막 파일을 다시 렌더링한다. 오래된 PNG 미리보기로 수정된 PDF를 검수하지 않는다.

실제 독자에게 읽기 시험을 하지 않았다면 수행했다고 기록하지 않는다. 필요한 경우 짧게 “무엇을 비교하는가, 점 하나는 무엇인가, 어느 관계가 결론의 근거인가”를 확인한다.

## 핵심 비교의 전달과 참고 figure 대조

새 설계나 큰 구성 변경에는 설계 때 정한 ‘독자가 먼저 봐야 할 관계’를 최종 이미지에서 다시 확인한다. 사소한 문구 수정에 전체 절차를 반복하지 않는다.

- **비교의 위치:** 긴 본문 설명 없이 무엇을 비교하고 어느 간격·방향·분포를 읽어야 하는지 특정할 수 있는가? 의도한 결론뿐 아니라 작은 차이·반대 방향·조건별 예외도 보이는가?
- **공간과 위계:** 제목·부제·도식이 데이터보다 먼저 시선을 차지하지 않는가? 패널 축 안의 큰 빈 영역 때문에 관측값 간 비교가 작게 보이지 않는가? 패널 간격과 글자·기호 크기가 최종 표시 크기에서 균형을 이루는가?
- **범례와 색:** 범례를 찾느라 멀리 시선을 옮기거나 같은 정의를 반복해서 읽어야 하는가? 색과 기호가 실제 비교 대상을 즉시 연결하는가? 색을 없애는 것을 단순함의 목표로 삼지 않는다.
- **축과 스케일:** 자료와 기준선이 모두 읽히며 비교할 간격이 충분히 보이는가? 0부터 시작할 필요는 도형의 의미에 따라 판단한다. 확대 범위를 표시하고, 축 범위로 효과를 과장하거나 조건 차이를 숨기지 않는다.
- **원그림과 나란히 비교:** 설계에서 확인한 참고 원그림과 최종 출력을 비슷한 패널 크기로 놓는다. 패널 수가 다르면 전체 보기와 대응 패널 비교를 구분한다. 데이터 영역 비중, 글자·기호, 범례와 축을 구체적으로 대조한다. 유명 논문의 설정도 다른 지표·검정·축 의미에는 그대로 이식하지 않는다. 새 설계나 큰 구성 변경에서 참고 원그림을 대조하지 못했다면 전달 단계로 넘어가지 않는다.

기록은 ‘문제 없음’ 대신 **어떤 관계가 어디에서 읽히는지, 참고 그림과의 차이가 왜 필요한지, 무엇을 수정했는지**를 짧게 적는다. 수치·출력 검수를 통과해도 핵심 비교가 읽히지 않으면 완료로 판단하지 않는다. 문장을 더 붙여 해결하기 전에 배치를 수정하고 재확인한다.

## 결과 기록

기존 실행 노트에 다음을 기록하면 충분하다. 작은 수정마다 별도 문서를 만들 필요는 없다.

- 입력·plotting 코드·출력 위치와 주요 설정.
- 확인한 범위와 검수에 사용한 최종 파일.
- 발견한 문제, 수정 내용, 재확인 결과.
- 설계·해석에 필수적이지 않아 확인 대상에서 제외한 범위와 이유. 필수 사항은 확인하고 1단계에 반영하기 전까지 미확인 상태로 완료하지 않는다.

자료 오류는 과학적 수정이 필요하다. 잘림·판독 불가·범례 혼동은 완성본 전달 전에 수정한다. 설계·해석에 필요한 미확정 사항이나 자료 불일치를 발견하면 확인 후 1단계 설계에 반영하고 영향을 받는 제작·검수를 반복한다. 확인할 수 없다면 완성본으로 전달하지 않는다. 검사 도구가 지원하지 않는 항목은 다른 방법으로 확인한다.
