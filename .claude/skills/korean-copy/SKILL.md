# 한국어 문구 규칙

적용 대상은 연구 노트, 논문, 보고서, 계획서, 설명문, 슬라이드, 안내문, 화면 문구, 검증·오류 메시지, 툴팁, 안내 창, 코드 주석, 커밋 메시지, 채팅 답변 전체다. 기존 문구의 수정은 사용자 지시가 있을 때만 진행한다.

스킬 폴더에 `references/project.md` 가 있으면 해당 프로젝트의 용어 표와 기록 절차를 함께 적용한다. 프로젝트 문서의 규칙이 본 문서와 충돌하면 프로젝트 문서를 우선한다.

---

## 1. 원칙

- **전문 용어는 영문 원문 우선.** 원문에 영문 명칭이 있으면 해당 명칭을 그대로 사용한다. 영문 명칭이 없는 경우에는 한자어 전문용어를 사용한다. 순우리말로 풀어 쓰지 않는다. 한자어도 한국어다. 반대로 집착적인 순우리말이나 학회 표준 우리말도 근거가 되지 않는다.
- **영어 직역 금지.** 영어 명사·동사를 한 낱말로 옮긴 말(row→줄, dock→부두, trigger→방아쇠, asset→자산, buy leads→문의를 산다)은 사용하지 않는다. 전문 개념의 명칭은 직역하지 않고 영문 원어를 사용한다(covariance, ridge regression).
- **구어체 금지.** 일상 구어 동사(씁니다, 둡니다, 넣다, 빼다, 고치다, 보낸다, 나온다)로 전문적인 설명을 작성하지 않는다.
- **지시대명사·대명사 금지.** 이곳, 여기, 이렇게, 그것. 대상은 명칭으로 지칭한다.
- **동사의 명사화 남발 금지.** 기존 한국어 명사나 한자어를 사용한다.
- **엠 대시(—) 금지.** 한국어 문장에서는 사용하지 않는다. AI 문체의 대표적 표지다.
- **꺽쇠(「」) 금지.** 문서·화면 문구·채팅 답변에서 인용·강조용 「」를 사용하지 않는다. 엠 대시와 같은 AI 문체 표지다. 「오류 2건. 게시 후 …」처럼 명사구 머리말 뒤에 설명 문장을 잇는 구성도 같은 부류이므로 한 문장으로 작성한다.
- **의미가 하나로 읽히는 낱말.** 「판정」처럼 오해의 여지가 있는 말 대신 동작 하나를 지칭하는 한자어(송신, 기재, 제외, 지정, 수정)를 사용한다.
- **간결성.** 제목·표제·라벨은 대상이나 기능의 명칭으로 작성한다. 상세 설명은 본문·주석·안내 등 설명 위치에 기재한다.
- **수량의 대상과 단위.** ‘자료 4개’, ‘논문 3편’, ‘두 종류의 시약’ 등 무엇을 세는지 명시한다. 수사에 조사만 붙여 대상을 대신하거나, 영어 수량 표현을 그대로 옮겨 세는 단위를 생략하지 않는다. 종류 수·시료 수·반복 횟수는 구분하며, 정상적인 인용·코드 표현에 기계적으로 적용하지 않는다.
- **낯선 표기의 실제 대상.** 기호·약어를 다른 미정의 기호·약어로 치환하지 않는다. 어떤 대상의 어떤 측정값·조건·비교 기준인지 먼저 설명한다. 불필요한 신규 명칭 대신 문맥에서 사용하는 대상명을 유지한다.
- **중복 표시 금지.** 문서·표·화면이 이미 표시하는 정보를 문구로 반복하지 않는다(빈 좌석 목록 위의 「빈 좌석 15개」 등).

## 2. 대체 표현

| 사용하지 않을 말 | 사용할 말 |
|---|---|
| 값 | 해당 대상의 명칭: 금액, 가격, 수량, 일수 |
| 칸 | 입력란·검색란·기재란(란), 표의 세로는 열, 그 외는 항목 |
| 줄 | 표의 가로는 행, 개수는 개, 그 외는 해당 대상의 명칭 |
| 판 | 버전, 또는 명칭·사용 기한 |
| 새, 더하기, 담다 | 신규, 추가·등록, 선택 |
| 바꾸다, 바뀌었습니다 | 변경, 변경되었습니다 |
| 받은 | 수신 |
| 달별, 그달, 이 달 | 월별, 해당 월 |
| 적다, 실리다 | 기재하다 |
| 계산, 셉니다, 셀 수 없음 | 산출, 집계합니다, 집계 불가 |
| 넘어가다, 남다, 돌아가다 | 전환, 유지, 적용 |
| 늘림, 줄임, 고치기, 다시 ○○ | 증가, 감소, 수정, ○○ 설정 |
| 걸림, 걸린 사유 | 오류, 오류 사유(오류 K건, 오류 없음) |
| 처럼, 같은(예시) | 등 |
| 정합니다, 정함 | 지정합니다 |
| 바로 | 즉시 |
| 만든 사람 | 제작자, 이름은 성함 |
| 단위 없는 수량사(세 류, 1류마다) | 단위 명시(3개 류, 1개 류마다) |
| 원문 문장의 수식어를 분리해 만든 명칭(당초 접수번호) | 해당 문서의 정식 명칭 |
| 임의 줄임말 | 원문 명칭 그대로 |

표에 없는 낱말도 기준은 동일하다. 판단 기준은 구어에서 쓰이느냐가 아니라 **해당 분야의 원논문·공식 문서·법령·고시·표준 서식·실무 문서에서 실제로 사용하는 낱말인가**다.

## 3. 위치별 문장 형태

작성 전에 해당 위치가 상태를 표시하는 위치인지, 안내하는 위치인지 먼저 결정한다.

| 위치 | 형태 | 예 |
|---|---|---|
| 점검 목록, 표의 상태 항목, 요약, 상태 표시 | 명사구 | `처리 대상 3건` · `중복 없음` · `기재 대상 N건.` |
| 알림·안내문·안내 창 | 「-습니다」 문장 | 「…기록을 할 수 없습니다」 |
| 의무 | 「~해야 합니다」 | 「신청해야 합니다」 |
| 수신자에게 하는 권유 | 「~해 주세요」 | 「초대를 수락해 주세요」 |
| 목록·표의 경고 | 경고 표시 + 설명 | 「코드가 등록되지 않은 항목입니다.」 |
| 처리 시점에 반드시 확인할 사항 | 해당 항목 하단에 표시되는 문장 | |
| 수정됨 등의 상태 | 수정 표시 (경고 표시는 확인이 필요한 항목에만) | |
| 내용이 없는 문서·표·화면 | 「없는 대상」과 「필요한 조치」 두 부분 | |
| 오류 문구 | 가변 명칭 뒤에 조사 이(가)·을(를)을 붙인 문장. 쌍점 나열 금지 | |
| 복수 오류 | 항목마다 줄바꿈. 「 · 」로 한 행에 연결하지 않는다 | |

- 통과 문구와 오류 문구는 동일한 표현의 긍정·부정으로 대응시킨다(없음↔있음, 초과↔이내, 미충족↔충족).
- 상태가 둘이면 문구도 둘이다(정원 초과와 시간 경과를 한 문구로 통합하지 않는다).
- 경고의 강조 수준은 결과의 경중으로 결정한다.

## 4. 호칭

- 열람자의 직함을 단정할 수 없는 위치에는 특정 직함을 사용하지 않는다.
- 초대·안내 등 수신자가 읽는 문구의 주어는 초대하는 조직이다. 서비스·도구 명칭은 출처 위치에만 표기한다.
- 높임이 필요한 위치는 「께서」, 「께」, 「성함」 등 높임 어휘를 사용한다.
- 발표 자료에 1인칭 「나」를 사용하지 않는다. 채팅에서 임의의 호칭을 사용하지 않는다.

## 5. 신조어 금지

용어집과 운영 절차의 정본은 프로젝트가 지정한 `GLOSSARY.md`다.
Cosearch 기본 경로는 `obsidian/00_Meta/GLOSSARY.md`다. 관련 정의·영문 원문·금지어·감시어를 확인한다.
새 명칭은 용어집의 충돌 점검·정의 등재를 완료한 후 사용한다. 금지어는 대체하고,
감시어는 실제 정의에 부합하는지 대조한다. 정의의 근거는 용어집이 연결한 정본에서 확인한다.

AI 문체에서 가장 자주 반복되는 문제다. 영어 개념을 한 낱말로 옮기거나, 설명 대신 짧은 명사를 새로 만든다. 신규 명사가 필요하다고 판단되면 대개 설명이 부족한 것이다.

신규 낱말을 사용하기 전에 아래 순서로 확인한다.

1. 사용자가 대화에서 이미 사용한 표현
2. 동일 문서·표·화면과 관련 문서의 명칭
3. 원자료의 항목명·식별자
4. 1차 출처의 낱말: 원논문, 공식 문서, 법령, 고시, 표준 서식, 공식 연동 명세, 공공 용어 사전

아래 항목은 사용하지 않는다.

- 문서 편제 명칭(별첨2, 별표3, 제14장)
- 내부 작업에서만 사용하는 은어
- 설명 없는 변수명·자료 항목 식별자
- 내부 계획 번호(W4, Phase 2)
- 설명 없는 식별 코드. 식별 코드는 명칭과 병기한다.
- 항목 명칭 앞에 임의로 추가한 수식어(앞선, 지난)

신규 개념이 셋 이상인 보고서나 계획서는 첫머리에 용어 표를 배치한다.

## 6. 작성 전 점검

1. 위치의 성격을 결정한다(3절 표).
2. 용어집의 관련 정의·금지어·감시어를 확인하고 사용할 낱말을 5절 순서로 확인한다. 공개 문서는 동일 종류 문서의 공식 작성 예시부터 열람한다.
3. 문구 작성 후 검색 기능으로 금지어를 검사한다. 신규 작성·수정한 문장만 대상이다.

   검출 결과는 후보다. 실제 칸을 지칭하는 표현이나 코드 문법이면 유지한다.
   문서 문장이면 2절 표에 따라 대체한다.
4. 문서·표·슬라이드의 미리보기에서 문구와 줄바꿈을 확인한다.

## 7. 지적 시 절차

1. **낱말부터 특정한다.** 「어색하다」는 지적에 문장 전체를 재작성하지 않는다. 원인은 대개 낱말 하나다(「처럼」을 수정하며 「같은」을 추가하는 실수가 대표적이다). 어색한 부분을 되묻지 말고 특정해 수정한다.
2. **출처를 확인한다.** 어색한 낱말이 항상 조어인 것은 아니다. 1차 출처의 용어인데 목적어가 누락되어 어색하게 읽히는 경우도 있다.
3. **동일 부류를 전수 검사한다.** 지적된 낱말 하나가 아니라 동일 계열(셉니다·실린다·돌아간다)을 해당 문서·화면, 해당 세션 산출물, 채팅에서 검색해 일괄 수정·보고한다. 동사형도 포함한다(명사를 수정했으면 동사형도).
4. **신규 규칙은 기록한다.** 문체 규칙은 본 문서 2절 표나 해당 절에 한 행을 추가한다. 용어 정의·금지어·감시어는 `GLOSSARY.md`에 기록한다. `references/project.md` 에 기록 절차가 있으면 그 절차를 따른다.
